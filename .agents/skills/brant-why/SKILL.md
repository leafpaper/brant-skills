# Brant 操作「为什么」查询

数据是从他 2020-08 到 2026-11 的直播逐字稿、喊单、文字线里抽出来的,每条都带原话和出处(card_id)。两张核心表:
- **操作事件表**(`data/trades.jsonl`):每个买入/加仓/减仓/清仓/持有/观望/不买,带他当场说的理由和原话、所属持仓段、转仓线索、同场前后 15 分钟讲到的理念。
- **理念事件表**(`data/ideas.jsonl`):他每一次讲某条理念,带台账编号(如 P7)、修正后的说法、原话、同场前后 15 分钟的操作。

配套:持仓段、观点(推理链)、每场小结、事后复盘/自我修正、理念台账(有效期:持续/演进/情境化/过时)、**每日直播总结**(`data/daily/`,2026-10 起)、**预设与认错条件**(`data/presets.jsonl`:他说过的「跌到 X 加」「破 Y 认错」,以及后来有没有照做)、**分类成绩单**(`data/scorecard.json`)、**参考资料**(战绩检验报告、失误与修正版、规则检验报告等)。

## 先做两件事
1. **看技能目录里有没有 `READER.md`**,有就先读:它说明使用者是谁、怎么称呼。没有这个文件时,使用者是整理这个项目的人,下文的「他」指 Brant。
2. **被问「你能做什么 / 有什么功能 / 怎么用」,或者使用者第一次用到本技能时**:跑 `python scripts/why.py --intro`,按输出用自己的话介绍——数据范围、能做的十一类事(每类带一个例句)、建议从哪开始、做不了什么。不要只贴命令;做不了的那几条要说。

## 怎么查(先查再答,不凭记忆回答)
在本技能目录运行(只用 Python 标准库;系统里命令叫 `python3` 的就用 `python3`):
```
python scripts/why.py TSLA --from 2025-01 --to 2025-06            # 某标的某段时间的买卖
python scripts/why.py 特斯拉 --from 2025-04 --to 2025-06 --kind sell   # 为什么卖(止盈/止损/清仓)
python scripts/why.py TSLA --from 2025 --kind switch              # 为什么转仓
python scripts/why.py TSLA --from 2026-08 --kind skip             # 为什么没买/在等什么
python scripts/why.py --position P0580                            # 一整段持仓从开到平
python scripts/why.py --idea P7 --from 2026-07 --to 2026-08       # 某条理念那段时间怎么说
python scripts/why.py --date 2025-03-24                           # 某一天全貌
python scripts/why.py --daily                                     # 最新一场直播总结(--daily 2026-10-21 / --daily list)
python scripts/why.py --presets                                   # 还没了结的预设点位/认错条件(--presets TSLA、--presets all)
python scripts/why.py --lesson B5                                 # 一类失误/一条裁决/一条理念的事后检验与裁决(B5、J2、S13)
python scripts/why.py --grep "老王|王老师|沃尔老师" --from 2026     # 原文搜索:全部直播逐字稿 + 文字线里找关键词
python scripts/why.py --scorecard                                 # 分类成绩单(--scorecard 选股|离场|硬扛|大方向|期货|言行 只看一块)
python scripts/why.py --dossier ADBE                              # 个股档案:一只票的看法演变、持仓段结果、复盘、未了结预设
python scripts/why.py --open                                      # 数据里还没见平仓的持仓段(和真实持仓对账用)
python scripts/why.py --sql "select …"                            # 自由统计(先 --sql schema 看表和列)
python scripts/why.py --flag E03881 --note "实际是 TSLL"           # 记一条更正(--flag list 看已记的;--unverified 看待核实的)
python scripts/why.py --ref overview                              # 参考资料(--ref list 看全部)
python scripts/why.py --check-essay essays/某篇.md                 # 核对文章里的每句原话和出处(写长文必做)
python scripts/why.py --topic "杠杆|融资"                          # 按关键词找理念(不知道编号时用)
python scripts/why.py --intro                                     # 功能介绍
```
- 时间写 `2025`、`2025-03` 或 `2025-03-24` 都行。杠杆/反向 ETF 按底层标的归并(问 TSLA 会带上 TSLL)。
- `--kind` 默认 `trade`(买入+减仓+清仓+其他);`buy` 只看买入/加仓,`sell` 减仓+清仓,`switch` 转仓,`skip` 观望+不买,`hold` 持有,`all` 全部。问「为什么不买/在等什么」一定要加 `--kind skip`。
- 输出太长:脚本会给按月分布,先挑关键月份再细查;或加 `--brief`(每笔只留理由和 2 条理念);`--position` 看整段。事后复盘默认看到区间结束后 120 天、最多 10 条,用 `--after N`、`--hmax N` 调。
- 要写某条理念的有效期怎么演进(旧版/新版、哪年改的),事件输出里只有〔演进〕这类标签,**另跑 `--idea <编号>`** 拿台账陈述和有效期说明。理念编号不知道时,先 `--topic 关键词` 找(问「他对止损怎么说」这类问题从这里开始),也可以从「同场讲到的理念」里找,或查理念目录(`--ref rule-catalog`)。

## 输出里的编号和字段
- **出处(card_id)**:`20250409_NuNNHeThW2M#14`(直播场次#卡号)、`text:2025Q2#0`(文字线)、`call:20934`(喊单)。引用原话时写这个。`E03881` 是事件号,`P0580` 是持仓段号,用来再查,不是原话出处。
- **时间**:直播卡的 `01:41:38` 是**直播进度**(开播后多久),不是钟点;喊单和文字线的时间是美东钟点。回答里写日期即可,需要时注明是哪种。
- **他语气里的把握(强/中/弱)**:抽卡时按他说话的确定程度标的,不是抽取置信度。
- **事件表不记股数**:「清仓」是事件分类(他说卖出/止损),不保证全部卖光;后面又出现「加回」「强平多少股」时,以原话为准。
- **文字线持仓卡**汇总了一整段持仓的每一步,挂在其中某个事件下;第一次出现时全文展示,之后写「见上文」。
- **⚠ 标记**只在有问题时出现:标的/价格没核实、讲者不确定、理由像是在回答听众(「会员问…」)——最后这种多半是给听众的建议,不是他自己的操作。
- **理念后面的方括号标记**(裁决 J36/J61/J68):〔含他本人做法〕陈述里有他本人的做法(自述,实盘规模无法核实),和他对听众说的规则可能不同;〔给听众的建议(…)〕括号里那部分是讲给听众的;〔他说得多、自己做得少〕他讲得多、自己很少这么做(长线类理念多是这样,J68);〔含改进建议〕有项目补的、不是他原话的部分;〔B1例外〕涉及他给最信的票(主要是特斯拉)开的例外;〔不进技能〕只适用于平台/展示账户/考核账户或日内的做法,不算他的理念(J61)。`--idea`、`--lesson` 里会展开成「标签」「条件依据」「检查题」「偏差提示」「同票/同一件事短期改口」几行。
- **条件依据**:「原话」条件是他说的;「原话(主观)」分界是他当时的主观看法(有没有方向判断、还看不看好这只票),配了检查题;「推断」条件是整理时推断的,他原话没明说;「无稳定分界」同一时期两种说法并存,不编条件。
- **裁决(J 编号)和「用户裁决」**:整理这个项目的人逐条定的处理办法(比如某条算不算他的理念、修正版怎么写),不是 Brant 说的。

## 怎么回答
按这个顺序,每一点都要能指到脚本输出里的原话:
1. **一句话结论**:他那次为什么买/卖/换。
2. **他当时自己说的理由**:引原话,注明日期、时间、来源(直播/文字线/喊单)。这是最硬的依据。
3. **背后的理念**:从「同场讲到的理念」里挑**和他理由对得上的**那几条,写台账编号和名字,并说明这条理念的有效期(如「P2 看好的票下跌:先正股→两倍→期权,演进:2025-02 起才加入两倍这一级」)。
4. **当时的大方向和板块判断**:用当天的观点和小结(大盘怎么看、为什么)。
5. **后来怎么处理、事后怎么说**:持仓段怎么结束的,复盘/自我修正里有没有提到这笔。
6. **事后检验与项目裁决**:先讲完他当时怎么想,再讲事后数字;数字一律注明口径。输出里有这几种:
   - 离场下「事后(C 口径)」:卖后 4 周标的 vs QQQ(同一标的 5 个交易日内的离场合并算一次,数字挂在组首那一笔);
   - 持仓段下「B 口径」入场后 12 周相对 QQQ、「D 口径」跌破止损线(正股 −15%/杠杆 −25%)后继续拿 vs 当天止损、「再犯检测 Kn」;
   - `--idea` 的证据等级(修订版为主,原版并列)、单条回测 T1–T7、相关裁决 Jn;`--lesson` 看裁决全文和修正版出处。
   使用者关心「这类做法到底好不好」时,引用裁决的结论和整体主检验(`--scorecard 总表`),不要拿单笔数字下结论。

## 问「哪类做法赚钱」时(分类成绩单)
- `--scorecard` 先给四个维度的正式判定,再给事后分组:选股按买入理由、行情、年份、把握、仓位大小;回避和做空准不准;离场按全清/减仓、止盈/止损;硬扛的代价和分层;大方向命中率与言行一致;指数期货波段;预设执行率。
- **只有「正式判定」能下结论**。分组全是事后分的〔探索性〕:回答时带上样本量和区间,区间跨 0 的说「分不出来」,不跨 0 的也只说「待验证的线索」。不要把分组结果说成规则,更不要说成现在该怎么做。
- 讲整体结论时先读 `--ref overview`(十条发现,每条带数字和出处);引用离场(C)时原版和修订版并列。
- 买入理由是机器打的标(约两成误差),单只票的类别拿不准时看原话。

## 看一只票的全貌(个股档案)
- `--dossier 代码`:概览、每段持仓和结果、按季度的看法时间线、两周内看法反转、观望/不买、事后复盘、还没了结的预设。先看这个再决定往哪细查(`代码 --from … --kind all`、`--position`)。
- 单只票的数字只是这只票的样本,不能说明他整体好坏;「两周内看法反转」只列事实,为什么变看原话,不替他补原因。

## 问最新直播 / 预设时
- 「今天/最新一场讲了什么」:先跑 `--daily`,照总结回答;要细节(某笔理由、原话)再跑 `--date <那天>`。总结开头写了日期,回答里要说是哪天的直播(数据定格在导出那天,最新一场不一定是今天)。
- 「在等什么价位/还有哪些计划」:跑 `--presets`。「待触发」只表示后面的直播里还没见到了结,不代表价格没到。
- 2026-07 之后的数据是留出期:理念卡标「新」的还没进台账,有效期没判过;标「还没做忠实度复核」的以原话为准;不给战绩数字。

## 问人物、往事、某句话时(原文搜索)
打包数据只抽了操作和投资理念;人物关系(某位老师、同事)、公司和平台的事、他讲的往事(爆仓、被强平)、观众反应、「有没有说过 X」这类问题,上面几种查法多半查不到,用 `--grep`:
- 搜的是全部直播逐字稿和文字线原文。发行包里原文在技能的 `data/transcripts`、`data/corpus`;在 brant-lens 项目里直接读项目的 `transcripts/`、`corpus/`(项目不在默认位置时设 `BRANT_LENS=项目路径`)。
- 关键词是正则,几种写法用 `|` 连。转写常把名字和词听错,**错字对照表 `aliases.json`**(本技能目录)里收了的会自动带上:搜「老王」会一起搜沃尔老师/温尔老师/沃伦老师/汪老师/Crazy王…,搜「强平」会带上「强评」(转写里「强评」反而最多),`--exact` 关掉。输出里「各写法命中行数」显示每种写法各命中多少。
- 先宽搜看「按月/按年分布」,再用 `--from/--to` 缩到关键几场;`--src talk|text` 只搜直播或文字线,`--ctx N` 多带几行上下文,`--max N` 多列几处。
- **对照表要边用边补**:查的过程中发现新的听错写法(上下文能确认指的是同一个人/同一件事),就把它加进 `aliases.json` 对应组,或者新开一组,`note` 里写明在哪场确认的;改完在回答末尾一句话说加了什么。只加确认过的;单字、常用词会误伤,不要加。技能目录只读、改不了对照表时,用 `--flag 总体 --tag 其他 --note "转写错字:X = Y,在某场确认"` 记一条。
- 引用原话时**照抄转写**,不要替他改字;第一次出现时注明错字对应谁(如「沃尔老师(即王老师,转写错字)」)。
- 输出的 `▶` 是命中行,`⚠` 是代班/别的老师在讲。直播时间是进度,文字线是美东时间;引用时写日期 + 进度和场次号。
- **这是没核对过的原始转写**:逐字稿只录他的声音,但他常把观众留言念出来——前后像在回留言、或第三人称说「布布」的,多半是他在念,回答里要说明「可能是念的留言」。别把命中次数当结论;语气拿不准的,建议按日期和进度回看视频。
- 原文是付费直播内容:回答里引必要的几句就够,不要大段转贴。

## 临时统计(--sql)
固定查法答不了的聚合问题(「2024 年半导体买入按月多少笔」「看多观点里后来买了的占多少」)用 `--sql`:
- 先 `--sql schema` 看表、列、取值和例子;只读,只能 select。
- **临时统计不是检验**:回答必须带样本量;分组小于 20 的只当例子;结论只说「待验证的线索」,不能推翻 `--scorecard` 的正式判定。
- 留出期(2026-07 起)没有战绩数字,不要自己拿行情去补算。
- 同一个问题换着切法试了好几次才出现的「规律」,要告诉使用者是试了几种切法之后看到的。

## 数据记错了、要补充时(更正入口)
这份数据是整理出来的,有记错的地方(`--ref known-issues`)。使用者指出错误或补充信息时:
- **立刻记下来**:`--flag <编号> --note "<他的原话或更正内容>"`。编号用事件号(E…)、持仓段号(P…)、卡片出处、理念编号;都没有就写标的或「总体」。照使用者的意思写,不替他润色、不加推断。
- **类别**用 `--tag`:`更正`(默认,数据记错了)、`事后补充`(当时没说、现在才补的理由或背景——**单独标注,不能混进当场原话**,事后的解释容易被后来的结果带着走)、`确认无误`。
- 记完告诉使用者:这条**还没改动数据**,查询结果要等整理者改完源头、重新导出才会变。更正记在技能目录的 `feedback/corrections.jsonl`;技能目录只读时(Codex 默认如此)记在当前目录的 `brant-feedback.jsonl`——脚本输出的「写在」一行是实际位置,照它说。把这个文件提交推送或发给整理者,才会回流。
- 使用者愿意帮忙核实时,`--unverified` 列出只有本人能确认的条目(标的没认出来的事件、理由说不清的持仓段),一次给几条,不要一口气倒几十条。
- 更正还没并进数据之前,回答里涉及那一条时要说「数据里记的是 X,你已更正为 Y」。

## 可选:券商连接器(长桥 / IBKR / Robinhood)——持仓和行情
这里只有历史记录:没有行情数据,也没有任何券商账户的数据。会话里接了券商连接器时,可以借它补两样:**真实持仓**和**行情**。都**不是必须的,没有也照常回答**;每样一次对话只提一次,对方不接就不再提。
- **怎么找工具**:看会话里有没有券商的连接器(MCP)或命令行。例如长桥的持仓、历史成交、K 线、报价查询,IBKR 的账户持仓、账户成交、历史价格、价格快照;Robinhood 看接的是什么连接器。工具名以会话里实际有的为准;一个都没有,就请使用者贴数据或导出的 CSV。
- **只读**:只调查询类工具(持仓、成交、订单历史、行情)。**不下单、不改单、不撤单、不建提醒、不改自选**——即使使用者说「顺便帮我卖了」,也说明这不在本技能范围。读账户之前先问一句「要读取账户持仓吗」,同意了再调;查行情不用问。

### 持仓对照
- **什么时候提**:使用者问到自己现在的持仓、说某只票「现在还拿着」、要核对 `--open` 的清单、或想知道展示账户和实盘差在哪时,提一句:「这个会话如果接了长桥、IBKR 或 Robinhood,我可以只读地调出当前持仓和成交记录来对照;没接的话,贴一份持仓或导出的 CSV 也行。」
- **拿到持仓后**:逐只跑 `--dossier 代码`(这只票上的历史、前几段结果、相关老毛病)和 `--presets 代码`(还没了结的预设);再和 `--open` 对一遍——数据里「没见平仓」而实际已清的、实际拿着而数据里没有的,问过使用者后用 `--flag` 记下。杠杆 ETF 按底层标的归并。
- **不做的**:不根据持仓给买卖建议(只讲这只票上的历史和当时定下的条件);不拿实盘盈亏去改这里的战绩数字;账户号、资产总额、持仓金额不写进更正文件或任何文件,除非使用者明说要记。

### 行情数据
- **什么时候用**(用得上时提一句「接了行情我可以查一下」):
  - **预设的价位到了没有**:`--presets` 里「待触发」的条件(「跌回 680 进场」「破 28450 清掉」),取现价或那天之后的最高、最低价,说到了没有、哪天到的。
  - **某笔操作之后走成什么样**:取那只票从操作日起的日线,说清楚起止日期和涨跌幅。
  - **价格没记或只有近似的**:事件表里价格是空的、或标着「收盘近似」的,取当天的价格做参照。
  - **给长文配走势图**(见「写长文」)。
- **没有行情就说没有**:连接器、使用者贴的数据都没有时,照实说「这里没有行情数据」,**不要凭记忆报价格**。
- **写清楚来源和口径**:每个行情数字注明来自哪个连接器、哪天取的、是否复权。跨过拆股的长区间(如特斯拉 2022-08、英伟达 2024-06)用前复权价,或注明未复权;直播里说的价位是当时的未复权价,对不上时说明是拆股造成的。期货(NQ / MNQ)、指数、ETF 的点位不是一回事,不要混着比。
- **和战绩数字分开**:行情只用来陈述事实(某天收盘多少、某段涨跌多少、价位到没到)。**不要自己拼出「留出期战绩」**,也不要把临时算的涨跌幅和 `--scorecard` 的检验数字并列比较:那些检验有固定口径(基准、观察期、同票合并规则),临时算的对不上。
- **仍然不给买卖建议**:「价位到了」是事实,可以说;「所以该买了」不说,做不做由使用者定。

## 写长文(某段时期或某个主题的操作与心路历程)
使用者要一篇「2022 年熊市是怎么过来的」「我在特斯拉上这几年」这类长文时可以写,**但每句引文都要过核对**:
- **先拉材料,再动笔**。按时间把那段的东西拉全:`代码 --from … --to … --kind all`(操作和理由)、`--date`(关键几天)、`--idea 编号 --from … --to …`(理念当时怎么说)、`--grep 关键词 --from … --to …`(往事和细节)、`--sql "select date,kind,subject,lesson,card_id from hindsight where date between … "`(复盘和自我修正,心路历程主要在这里)、`--dossier`、`--scorecard`。材料不够的时段照实写「这段没有直播记录」。
- **结构**:开头四行元信息(`title`、`period`、`written`、`summary`,上下各一行 `---`);`## 速览`(每行 `**标签**:内容`);`## 读这篇之前`(数据范围、哪些是事后回忆、金额是自述);正文按时间分节 `## 一、…`、`### 小节`;最后可加 `## 时间线`(每行 `- **时间**:事情`)。最重要的一句原话可以单独成行:`> 「原话」[[出处]]`。
- **引文写法**:原话用「」,**照抄转写,一个字不改**,后面紧跟出处:`[[20250509_7ZMWXJgEf9Q#26]]`(场次#卡号,就是查询输出里的 card_id)或 `[[20240924_mtaD4yBJRZI 00:27:41]]`(场次 + 直播进度)。「」只用于原话;术语、概括不要加「」。
- **内容上的规矩**:每个判断后面都跟得上原话;分清**当时说的**和**事后回忆的**(回忆的几次说法不一致就并列写);不替他补心理活动和理由;账户金额、盈亏是自述,写「他说」;不评价对错,事后检验的数字单独成段并注明口径;一处原话有几种理解的,写「可能是」。
- **写完必须核对**:`python scripts/why.py --check-essay 文章路径`,改到最后一行「问题 0」。「❌ 没找到」= 不是原话(压缩、改写过的也算),改成逐字的原话或去掉「」;「⚠ 出处标错」= 话是真的但场次不对,改出处;「没标出处」只允许出现在标题和速览里。没过核对的文章不要交给使用者,更不要说「已核对」。
- 文章存到使用者当前的工作目录(如 `essays/2022-熊市.md`),不要写进技能目录;发不发布、发在哪由使用者定。
- **走势图(可选,要有行情)**:会话里有行情连接器时可以配图,没有就不配、照实说。图表数据写在和文章同名的 `.json` 里,正文里单独一行 `{{chart 名字}}` 放图:
  ```
  {"charts": {"qqq": {"kind": "line", "title": "QQQ 收盘价与每个阶段的判断", "sym": "QQQ", "unit": "美元",
     "note": "QQQ 日收盘价,前复权(长桥行情,取于 2026-11-14)。圆点是当天直播里的判断。",
     "series": [["2021-11-01", 387.43], ["2021-11-02", 389.17]],
     "phases": [{"from": "2021-11-01", "to": "2021-12-31", "n": "①", "name": "还在牛市框架里"}],
     "marks": [{"d": "2021-12-08", "st": "多", "q": "逐字原话", "src": "20211208_J2KEy4T6Sn4#5", "what": "一句话说明"}]}}}
  ```
  `series` 是按日期升序的日收盘价;`phases` 的 `n` 和正文小节标题开头的 ①② 对上;`marks` 的 `st` 写 多 / 空 / 事,`q` 必须是逐字原话,`src` 是出处;`note` 写明行情来源、取数日期、是否复权。`--check-essay` 会把同名 `.json` 里的标注一起核。这个格式和整理者的网站一致,文章和 `.json` 交给整理者就能上网站。

## 参考资料(--ref)
`--ref list` 列出全部和各自的位置;文件大的只给目录,直接读文件。按问题选:
- 整体结论 → `overview`;数据哪里不可靠 → `known-issues`;术语 → `glossary`
- 四个维度的战绩细节 → `track-record`(原版,正式结论)、`track-record-v2`(修订版,并列)
- 某个老毛病、修正版、检查题 → `corrections`
- 某条经验有没有数据支持(困境反转、跟踪止损、压力位减仓、大佬持仓…)→ `rule-tests`
- 理念编号对不上 → `rule-catalog`;台账怎么来的 → `ledger-report`、`stage4-report`
- 最近怎么看 → `current-stance`(留出期,观点未经检验;超过 5 个交易日没更新要说明可能已变)

## 必须守住的
- **分清他明说的和推测的**:「同场 ±15 分钟讲到的理念」只是时间挨着,不等于就是这笔的理由。只有理由或原话对得上,才能说「这笔是按 X 理念做的」;否则写「同场他还讲了 X,可能相关」。
- **没记理由就说没记**:喊单本身不带理由;有的卡写「(卡上没记理由)」。不要替他补理由。可以去当天的观点和小结找线索,但要说明这是当天背景,不是他对这笔的解释。
- **转仓**:「他的理由里说了换仓」是明说;「同场一卖一买、两边相关」只是线索,要看两边理由有没有互相提到再下结论。
- **个股/当期判断别拔成通则**:理念卡标「本轮行情/个股判断」的,只说那段时间他这么看。
- **自己做法 vs 给听众的建议**:他常说「我自己满仓满融,你们别这样」——引用时分清楚。问「这条是他自己做的还是讲给听众的」,先跑 `--idea <编号>` 看标签:「他本人做法」「给听众的建议(…)」「他说得多、自己做得少」照标签说,并引原话;没有这几个标签的,不要自己下结论,回到原话看他是对谁说的(「你们」「会员问」多半是给听众)。标「他说得多、自己做得少」的,要带上 J68 的数据(2021 起明确清仓的做多正股 176 笔,持有中位 40 天;拿满一年的 31 笔,其中 19 笔是 2021~2022 买入、跨过熊市才清),别把它说成他的主要做法。
- **〔不进技能〕的理念**(目前 5 条:R12、R47、P44、M30、M66):是平台、考核账户或日内的规矩,裁决不算他的理念(J61)。可以讲他说过、为什么说,但要注明这一点,不当他的交易原则或止损依据。
- **条件依据是「推断」的**,回答时说「他原话没明说这个条件」;「无稳定分界」的,两种说法连同原话并列写,不替他编分界;有「偏差提示」的(他按自己持仓方向解读信号),讲到那类信号时要提。
- **同票/同一件事短期改口**:`--idea` 里列了卡片对和间隔,时间线里标 ↔改口。照原话说他前后怎么讲的,不替他补改口的原因。
- **⚠ 标记照实说**:事件表标了标的未核实(unknown_ticker / low_conf_unverified)或讲者不确定的,回答里要提。
- **单笔数字只是一个样本**:不能拿一笔说明他好或坏;整体结论看主检验。
- **〔探索性〕分组**(成绩单里的分组、卖出理由粗分、仓位大小粗分、临时统计)是事后分组,只能说「待验证的线索」。
- 裁决里写着「改进建议,非 Brant 原话」的部分,引用时照样标出。
- **修正版是对他过去模式的修正,不是对现在行情的建议**;问现在该不该买,仍说明不在本技能范围。
- **证据等级 C 不等于规则错**:C 是他自己常违反这条规则(言行相反多);规则本身好不好要看回测或裁决。
- **「检验没通过」不等于「错」**:只说明那种机械写法、那段时间、大盘股上看不出优势(`--ref rule-tests` §2.1)。
- **留出期**(2026-07-01 起)的持仓和离场写着「留出期,不进判定」,不要自己去算收益。有行情时可以陈述价格事实(哪天收盘多少、价位到没到),但不拼成战绩。
- **数据会过期**:输出里出现「⚠ 数据截至 …,距今 N 天」时,回答涉及「最近」「现在」的内容要先说这句。
- **只讲历史**:问「那现在该不该买」不在本技能范围,说明这里只解释过去为什么那么做、事后检验怎么说。
- **券商账户只读,行情只陈述事实**:见上面「可选:券商连接器」。
